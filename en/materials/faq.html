Frequently Asked Questions (FAQ)

Course-wide frequently asked questions (22 items in total), grouped into five categories: Study & Usage, R & Software, Statistical Concepts, CLPN Methodology, and Writing & Reporting. Individual lesson pages also include 'Common Questions & Pitfalls' specific to their topics.

Study & Usage

I have no prior background in statistics or programming. Can I really learn this?

Yes. The course starts from the mean and 'what is a variable' (1.1), and R starts from installation (2.1). The key is following the lesson order, running the code yourself in every lesson, and maintaining 5–7 hours per week.

Do I have to follow the lessons in order?

We strongly recommend following the 16-Week Plan. Prerequisites are listed at the top of each lesson page; if you have already mastered certain content, you can take just the quiz, and skip the lesson if you answer every item correctly.

Why did my progress disappear?

The 'completed' marks are saved in your browser's local storage. Switching browsers, using incognito mode, or clearing browser cache will erase them. Record important learning records in your Study Log.

Where are the exercise solutions?

Each lesson has expandable reference solutions for its exercises. For exercises requiring code, full solutions are in R/solutions/, included in the course archive on the Download page. Execution logs are in R/output/sol_*_log.txt.

R & Software

What should I do if package installation throws an error?

First check your internet connection, and configure a reliable CRAN mirror in RStudio (Tools → Global Options → Packages). Non-ASCII characters or spaces in Windows usernames or file paths often cause installation issues; we recommend placing the course in a simple path such as D:\clpn-course\. See the R Code User Guide for details.

Why don't my numbers match the website exactly?

Most scripts set a random seed, so results should match bit-for-bit. Bootstrap-related scripts (8.2, 8.3, 10.2) run on a single core by default; with a fixed seed, their results are also completely reproducible. If you set nCores greater than 1 (parallel processing), the seed does not govern child processes, and results will differ across runs. Edge weight confidence interval endpoints typically fluctuate only in the second or third decimal place, but the CS-coefficient does not vary continuously: it can only take values on the dropping-proportion grid (spaced by ~0.08), so it can jump by an entire step. In our course data, in-EI fluctuates between 0.44 and 0.52, landing once above and once below 0.5, changing the qualitative conclusion. For reported results, always run single-core with a fixed seed. In addition, minor differences can arise from different R or package versions.

Special characters or fonts display as boxes or garbled text?

For plot labels: _setup.R attempts to set appropriate plot fonts; if issues persist, see common mistakes in 2.6. For data encoding issues when reading CSV files, see 2.4.

Should I use Quarto or R Markdown?

Either works. Course examples use Quarto (R/solutions/week06.qmd); if Quarto is not installed, the same content can be adapted to an .Rmd file and rendered with rmarkdown.

What is in _setup.R?

It locates the course root directory, configures output paths and plot fonts, defines item names, and loads utility functions (clpn_estimate(), cl_only(), edge_list(), etc.). It is well worth reading, but does not need modification.

Statistical Concepts

What actually is a p-value?

The probability of observing data as extreme as or more extreme than the observed data, assuming the null hypothesis is true. It is NOT the 'probability that the null hypothesis is true', nor does it measure effect size. See 1.6.

The correlation is significant but the regression coefficient is not—is something wrong?

No. A regression coefficient represents the 'unique' association after controlling for other predictors, which answers a fundamentally different question from bivariate correlation. Social support in the course dataset is a prime example (2.5).

Why use LASSO instead of standard linear regression?

With many nodes, standard OLS regression produces many small coefficients that are 'non-zero merely by chance' (overfitting, false positives). LASSO shrinks small coefficients exactly to zero, yielding a sparser, more interpretable network, at the cost of shrinkage bias in the retained coefficients. See 3.5 and 6.3.

Should I choose lambda.min or lambda.1se?

lambda.min minimizes cross-validation prediction error and retains more edges; lambda.1se is more conservative and produces a sparser network. Pre-specify one in your analysis plan as the primary analysis (this course uses lambda.min) and use the other as a sensitivity check. See 7.2.

What is the difference between between-person and within-person effects?

Between-person: whether individuals who are more lonely than others are also more depressed; within-person: when an individual is more lonely than their own usual level, are they subsequently more depressed. Standard CLPM and CLPN conflate these two levels. See 4.1 and 5.3.

CLPN Methodology

Do CLPN edges indicate causality?

Not directly. Edges represent 'temporal prediction after controlling for all T1 nodes', which can be influenced by stable traits, unmeasured confounding, and the choice of measurement lag. In writing, use terms like 'predicted' or 'consistent with', and avoid causal claims like 'caused' or 'drove'. See 5.4.

How large a sample size is required?

There is no universally accepted rule of thumb such as 'N must be at least X times the number of nodes'. The ratio N/p (sample size divided by number of nodes) is only a crude heuristic: when it is small, each nodewise regression has little information, leading to sparser and less stable networks. With 9 nodes there are 81 coefficients; in the course data N/p = 800/9 ≈ 89. The actual sample size needed depends on the hypothesized true network (edge density and strength) and the specific research question, and should be evaluated via simulation: Constantin, Schuurman, and Vermunt (2026) provide a general Monte Carlo framework for sample size planning in network models, demonstrated in a simplified version in Lesson 7.6. After data collection, evaluate stability using bootstrap and the CS-coefficient; see 8.2 and 8.3.

Can I estimate a CLPN with only two waves of data?

You can estimate a T1 → T2 network, but you cannot test replication across a subsequent lag interval, nor can you use RI-CLPM to separate stable traits (which requires at least 3 waves). State this clearly in your limitations section.

Is the node ranked highest in centrality the optimal intervention target?

No. First confirm that CS ≥ 0.25 (preferably ≥ 0.5) and that the difference between the first and second ranked nodes is statistically significant via bootstrap testing. Even then, high centrality only reflects 'strong predictive associations'. Whether intervening on that node produces change requires experimental intervention studies. See 6.5 and 7.4.

Is the course dataset real data?

The main panel used in the lessons is simulated (N = 800, 3 waves of community adult residents) according to a predefined true structure (data/simulate_data.R), which allows us to verify whether the methods recover the true structure (the population target and within-person truth; see 7.2). See the Data Dictionary for details. In addition, two real public datasets are included: the sports coaches mental health panel for the Lesson 7.6 exercise (CC0, bundled in the course package); and the ELSOC Case using PHQ-8 from the Chilean Longitudinal Social Survey (CC0, preprocessed analysis file bundled). Sources, licenses, and citation formats for both are provided in the Data Dictionary.

Writing & Reporting

What details are most frequently omitted in methods sections?

The λ selection rule, number of CV folds, random seed, whether items were standardized, whether covariates were penalized, whether centrality calculations include autoregressions, number of bootstrap resamples, and the CS criterion. Check against the Reporting Checklist item by item.

How do I ensure numbers in the results section are error-free?

Every number should be traceable to a specific output file (see the 'number-to-file' cross-reference table in 10.2). It is best practice to insert values automatically using Quarto inline code rather than copying by hand.

How should I write the limitations section?

Include at least: standard CLPN conflates between-person and within-person effects; observational data cannot rule out unmeasured confounding; conclusions are dependent on the chosen time lag; and sample representativeness. See 10.3.
