## ① Intuition A Row of Storage Slots: Vectors

**Sleep records for ten clients**

The 10 members of a community sleep-health group reported how long they slept last night (in hours): 7, 5.5, 8, (member 4 left it blank), 6, 4.5, 7.5, (member 8 left it blank), 9, 5. You want to know: how long did they sleep on average? Who slept less than 6 hours and needs closer follow-up? In Excel you would type these into one column; in R you store them in a vector.

A vector is a row of values of the **same type**, in order, with each position numbered (starting at 1). You create one with `c()`:

`sleep <- c(7, 5.5, 8, NA, 6, 4.5, 7.5, NA, 9, 5)`

The `NA` here (Not Available) is R's special symbol for a missing value (NA). It means "there should be a value here, but we don't know what it is." It is not 0, and it is not an empty string.

**Analogy: a numbered row of storage slots**

A vector is like a row of numbered storage slots. `sleep[3]` means "open slot 3," which gives 8. A data frame (next lesson) is many such rows placed side by side: each row of slots is one variable (one column), and the same position in every row belongs to the same person.

### Indexing: taking out the slots you want

Square brackets `[ ]` do indexing. There are three ways to use them:

- **By position**: `sleep[3]` takes the 3rd value; `sleep[c(1, 3)]` takes the 1st and 3rd; `sleep[-1]` takes everything except the 1st (minus = drop). R counts from 1: `sleep[0]` does not give an error but returns an empty vector, so this kind of mistake is hard to spot.

- **By condition (logical indexing)**: `sleep[sleep < 6]`. R first computes `sleep < 6`, which gives a run of TRUE/FALSE values, and then takes the values at the TRUE positions. So `x[x > 5]` means "take every value of x that is greater than 5."

- **By name**: if the elements of a vector have names, you can write `v["lone1"]` (in a data frame you usually write `df$var`; next lesson).

(Interactive widget: vecidx)

### Vectorization: doing the same thing to every slot at once

R's operations are vectorized: `sleep * 60` multiplies every value by 60 (converting to minutes), with no loop needed. `sleep < 6` also compares each value separately. Adding two vectors of the same length adds them position by position. This keeps R code short: `(x - mean(x)) / sd(x)` turns a whole column into z-scores in one line (Lesson 1.3).

### Data types: what is in the slots

Every vector has a data type, which you check with `class()`:

| Type | Example | Used for |
| --- | --- | --- |
| numeric (including integer) | `7`, `5.5`, `3L` | Scale scores, age, sleep duration |
| character | `"Xiao Li"`, `"P001"` | Names, IDs, open-ended answers; must be in quotes |
| logical | `TRUE`, `FALSE` | Results of comparisons, filter conditions |
| factor | `factor(c(1, 0), levels = c(0, 1), labels = c("Male", "Female"))` | Categorical variables: gender, education level, service type |

Two key rules:

1. **A vector can have only one type.** If you mix numbers and text, R turns every value into text: `c(1, "two", 3)` gives three strings. In questionnaire data, a single cell where someone typed "five" makes the whole column read as character, and `mean()` then fails. So after importing data, first check each column's type with `class()` or `str()`. Forcing a conversion, `as.numeric(c("3", "4", "five"))`, gives `3 4 NA` and the warning `NAs introduced by coercion`.

2. **Logical values can be used as numbers**: TRUE = 1, FALSE = 0. So `sum(sleep < 6, na.rm = TRUE)` is "the number of people who slept less than 6 hours" (3), and `mean(condition)` is "the proportion who meet the condition."

### Why is gender better stored as a factor?

In the course data, `gender` is stored as 0/1. If you treat it as a number, R assumes "female (1) is one unit more than male (0)" and will compute a mean (0.534). For a 0/1 variable the mean equals the proportion in the category coded 1 (here, 53.4% women), so it still means something. But for a variable with three or more categories (such as "service type: 1 casework, 2 group work, 3 community work"), treating the category codes as numbers is wrong: "community = 3 times casework" makes no sense. Once stored as a factor:

- R knows it is a category: `table()` and `summary()` give the count in each category (male 373, female 427).

- In a regression, R turns the factor into dummy variables automatically, with the first level as the reference group.

- Plots color by category automatically and label the groups "Male / Female" instead of 0 / 1.

- `mean()` on a factor returns NA with a warning, which blocks a meaningless calculation.

### The missing value NA: an unknown that spreads

`mean(c(1, NA, 3))` returns `NA`. The logic is simple: if one value is unknown, the mean is unknown too. To compute from the known values, add the argument `na.rm = TRUE` (NA remove): `mean(c(1, NA, 3), na.rm = TRUE)` returns 2. `sum()`, `sd()`, `min()`, and `max()` all have this argument.

**NA and comparisons**

`NA < 6` is still `NA` (unknown). So `sleep[sleep < 6]` returns `5.5 NA 4.5 NA 5.0`, with two NAs mixed in. The correct version adds "and not missing": `sleep[sleep < 6 & !is.na(sleep)]`. `is.na()` checks each value for missingness, `!` means "not," `&` means "and," and `|` means "or." `which(sleep < 6)` ignores NA automatically and returns positions 2, 6, 10. You also cannot find missing values with `x == NA` (the result is all NA); you must use `is.na(x)`.

### Matrices and lists: two relatives of the vector

Later lessons use two more structures, so meet them now:

- **Matrix**: a two-dimensional table with rows and columns in which every element has the same type. `glmnet` requires the predictors as a numeric matrix (`as.matrix()` in Lesson 3.5); the CLPN result B is also a 9 × 9 matrix, and the entry in row *i*, column *j* is `B[i, j]`: before the comma is the row, after it the column. A data frame (Lesson 2.3) is also a two-dimensional table, but each column can have a different type; to hand a data frame to a function such as `glmnet` that accepts only matrices, first make sure all columns are numeric, then convert with `as.matrix()`.

- **List**: a "big bag" that can hold things of different types and lengths. Many functions return lists; for example, the result of `lm()` holds the coefficients, residuals, fitted values, and more, and you take out one part with `$`, as in `fit$coefficients`. The `sessionInfo()$R.version$version.string` in Lesson 2.1 was digging down through a list one level at a time.

**Quick reference: functions in this lesson**

| Function | What it does |
| --- | --- |
| `c()` | Combine into a vector |
| `length()` | Number of elements |
| `class()` / `str()` | Show the type / structure |
| `is.na()` | Check each value for missingness |
| `which()` | Positions that are TRUE |
| `table()` | Counts (frequency table) |

**Social work context: missingness is information**

`na.rm = TRUE` just skips missing values, which means using only the people who have data. In needs-assessment questionnaires, many people leave "household income" blank. Computing mean income with `na.rm = TRUE` may overstate how well off the community is, because the poorest households are often the least willing to answer. So before using `na.rm`, check how much is missing with `sum(is.na(x))`, and think about who did not answer and why (Lesson 4.3 is about missing-data mechanisms).

### Writing your own functions

When you need to do the same operation many times, you can wrap it in a user-defined function:

`zscore <- function(x) (x - mean(x, na.rm = TRUE)) / sd(x, na.rm = TRUE)`

Read it as: create a function named `zscore` that takes one input `x` and returns "x minus the mean of x, divided by the standard deviation of x." If the body is longer, wrap it in curly braces `{ }`; the value of the last line is what the function returns. After that, `zscore(sleep)` is as easy as `mean()`.

## ② Essential Math Vector Notation

$$\mathbf{x} = (x_1, x_2, \dots, x_n)$$

\(\mathbf{x}\)Bold means a vector (a whole column of numbers).\(x_i\)The \(i\)-th element, R's `x[i]`.\(n\)The number of elements, `length(x)`.

Vectorized operations work element by element: \(60\mathbf{x} = (60x_1, \dots, 60x_n)\), \(\mathbf{x}+\mathbf{y} = (x_1+y_1,\dots,x_n+y_n)\). The z-score function:

$$z_i = \frac{x_i-\bar x}{s_x},\quad i = 1,\dots,n$$

\(\bar x\) and \(s_x\) are computed from the non-missing values only (that is what `na.rm = TRUE` does); for a missing \(x_i\), \(z_i\) is still NA. Summing logical values: \(\sum_i \mathbb{1}(x_i<6)\), where \(\mathbb{1}(\cdot)\) is 1 when the condition holds and 0 otherwise, which is `sum(x < 6)`.

### Worked example: missing values, type conversion, and recycling

For each line below, predict the result first, then run it in R to check. All of these come up for real when you write CLPN scripts.

```r
x <- c(3, NA, 5, 2)
mean(x)                    # NA: one missing value makes the result NA
mean(x, na.rm = TRUE)      # 3.333...: (3 + 5 + 2) / 3; the denominator is 3, not 4
sum(is.na(x))              # 1: TRUE is added as 1; the usual way to count missing values

c(1, "2", 3)               # "1" "2" "3": one character value turns the whole vector into character
as.numeric(c("4", "five")) # 4 NA, with the warning NAs introduced by coercion

f <- factor(c("10", "20", "10"))
as.numeric(f)              # 1 2 1 ! You get the level codes, not the original numbers
as.numeric(as.character(f))  # 10 20 10: convert to character first, then to numeric

c(1, 2, 3, 4) + c(10, 20)  # 11 22 13 24: the shorter vector is reused (recycling)
y <- c(8, 6, 9)
y[-1]                      # 6 9: minus means "drop the 1st"
y[y > 7]                   # 8 9: a logical vector as the index
```

Line by line:

- **NA spreads.** R does this on purpose: it never quietly ignores missing values. When you compute total scores for a CLPN, `rowSums()` returns NA by default if any item is missing, and you have to decide explicitly how to handle it (Lesson 4.3).

- **A vector has only one type.** When importing from Excel, text such as "missing" or "not applicable" also turns the whole column into character.

- **The factor trap.** Inside, a factor stores codes 1, 2, 3, … with labels attached on the outside. Calling `as.numeric()` directly gives you the codes. Data imported from SPSS often carry such labels, so be careful.

- **Recycling.** When two vectors have different lengths, R repeats the shorter one. If the longer length is an exact multiple of the shorter one, R gives no warning, so a wrong length can silently give a wrong result.

**Common mistakes**

- **Forgetting to save the result with assignment.** `sort(x)` only shows the sorted values; `x` itself is unchanged. You need `x <- sort(x)`.

### Function arguments: by position or by name?

In the call `round(3.14159, 2)`, 3.14159 and 2 are two **arguments**. R lets you pass arguments by position (the 1st is the number to round, the 2nd how many decimals to keep) or by name: `round(x = 3.14159, digits = 2)`. Naming them is clearer, and then the order doesn't matter. A good habit: give the 1st argument (usually the data) by position and name all the others, as in `mean(x, na.rm = TRUE)` or `cor(x, y, use = "pairwise.complete.obs")`. When you come back to the script six months later, you will still see at a glance what each setting means.

### How to read a help page

Lesson 2.1 introduced the Usage, Arguments, and Examples sections of a help page. Two more points. First, in Usage, what follows an equals sign is the default; when the default is a vector, the first element is used, so `method = c("pearson", "kendall", "spearman")` in `?cor` means Pearson by default. Second, the **Value** section says what the function returns (a vector, a matrix, or a list), which decides whether you then use `[ ]` or `$` to get at the result.

## ⑤ Exercises Hands-On Practice

#### Exercise 2.2-A: A sleep vector

Store the sleep durations of 10 people in a vector (with 2 NAs), compute the mean, and find the people who slept less than 6 hours. Write a function `zscore(x)` that returns the standardized vector and compare it with `scale()`.

Reference code

```r
sleep <- c(7, 5.5, 8, NA, 6, 4.5, 7.5, NA, 9, 5)
mean(sleep, na.rm = TRUE)                    # 6.5625
which(sleep < 6)                             # 2 6 10 (which people)
sleep[sleep < 6 & !is.na(sleep)]             # 5.5 4.5 5.0 (their hours)
zscore <- function(x) {
  m <- mean(x, na.rm = TRUE)
  s <- sd(x, na.rm = TRUE)
  (x - m) / s                                # The last line is the return value
}
all.equal(zscore(sleep), as.numeric(scale(sleep)))   # TRUE
```

Points to cover: say how NA is handled; explain why `which()` gives positions while brackets give values; `all.equal()` checks whether two results are equal (within floating-point error).

#### Exercise 2.2-B: On the course data

Read `data/clpn_sim_wide.csv` and store the column `dep1_t1` (Depressed mood, scored 0–3) as a vector `d1`. (1) How many people scored 3? (2) What proportion scored 2 or higher? (3) Standardize `d1` with your `zscore()` and check that the result has mean 0 and standard deviation 1.

Reference code

```r
dat <- read.csv("data/clpn_sim_wide.csv")
```

#### Exercise 2.2-C: A factor with several categories

Create the vector `service <- c(1, 3, 2, 2, 1, 3, 3)` (1 casework, 2 group work, 3 community work). Turn it into a factor with English labels, count with `table()`, and explain why `mean(service)` (on the numeric version) is meaningless.

Reference answer

```r
service <- c(1, 3, 2, 2, 1, 3, 3)
service_f <- factor(service, levels = 1:3, labels = c("Casework", "Group", "Community"))

```

`mean(service)` = 2.14, and "the average service type is 2.14" means nothing: 1, 2, 3 are only labels, and 10, 20, 30 would do just as well.

## Summary Three Takeaways

- A vector is a row of values of one type; `[ ]` takes values by position, condition, or name; operations are vectorized automatically.

- Four basic types: numeric, character, logical (TRUE = 1), and factor (categorical variables). If a type is wrong, everything downstream goes wrong.

- NA spreads: use `na.rm = TRUE` and `is.na()`, and think about why values are missing. Next lesson: [2.3 Data Frames and Introduction to the Tidyverse](L2-3.html).
