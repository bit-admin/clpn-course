Once you can read a paper, the next step is to evaluate it critically. ### Two new concepts in more depth

#### Topological overlap (item redundancy)

If two items ask almost the same thing (for example "I feel lonely" and "I feel lonesome"), the edge between them will be very strong, and their patterns of connections with the other nodes will also be very similar. This is not "two symptoms acting on each other" but "the same thing measured twice". Consequences: (1) the edge between the pair is misread as a dynamic relationship; (2) their centrality is artificially inflated. The `goldbricker()` function in the networktools package finds item pairs whose patterns of correlation with the other nodes are very similar, to help you decide whether to merge or drop items.

#### Researcher degrees of freedom

A CLPN involves many decisions that could go either way: lambda.min or 1se? Which γ? Which seed? Covariates or not? Which items? If a researcher tries many combinations and reports only the "nicest-looking" one, the result may be due to chance. The remedy: write an analysis plan in advance (Lesson 10.1) and report a sensitivity analysis: with another reasonable decision, do the main conclusions stay the same?

**Another reminder about out-EI:**

lone4 has the highest out-EI under all three λ rules, which looks "robust", but the CS in Lesson 8.3 is only 0.20, and lone4 does not stand out in either the population target matrix or the within-person truth matrix (Lesson 7.4). In a sensitivity analysis, "the conclusion does not change" is not the same as "the conclusion is correct": the different λ rules use the same sample and share its sampling error. So look at the sensitivity analysis and the bootstrap stability checks together.

### Fried & Cramer (2017): the big questions for network methods

Fried and Cramer discuss the challenges facing psychopathology network theory and methods systematically, including how nodes are defined and chosen, whether network results replicate across samples, and the distance between a statistical network and a theoretical "causal system". Reading it helps you place CLPN in a wider context: CLPN is a useful tool for description and for generating hypotheses, but it is not a machine that "reads off the causal network". (Take the specific arguments from the original paper.)

### How to structure a review

1. **Overall assessment** (2–3 sentences): research question, method, main contribution.

2. **Strengths** (2 points): specific and sincere, e.g., "reports a T2→T3 replication", "shares the code".

3. **Major issues** (3 points): each with "what the problem is → why it matters → a concrete suggestion".

4. **Minor issues**: wording, figures and tables, citations.

5. **Tone**: address the work, not the people; write "the authors could consider …" rather than "the authors wrongly …".

## ② Essential Math Write the Intuition as Equations

#### 1. Why does item redundancy inflate centrality?

Suppose items A and A′ are nearly identical: \(A' = A + e\), with \(e\) small. The A—A′ edge in the network (partial correlation or cross-lagged) will be large, and the strength/EI of both A and A′ goes up by about \(|w_{AA'}|\). If you merge the two items into one node, this "self-to-self" edge disappears.

#### 2. Measuring sensitivity to the seed

\[\pi_{kj}=\frac{1}{S}\sum_{s=1}^{S}\mathbb{1}\big[\hat\beta^{(s)}_{kj}\neq0\big]\]

| Symbol | Reading / Meaning |
| --- | --- |
| \(S\) | Number of seeds tried (S = 20 in R/L9-2) |
| \(\hat\beta^{(s)}_{kj}\) | The edge estimated with the s-th seed |
| \(\pi_{kj}\) | Proportion of seeds under which the edge is nonzero: 1 = always kept, 0 = always 0, in between = sometimes there, sometimes not |

#### 3. Agreement measures for a sensitivity analysis

\[r=\mathrm{cor}\big(\hat\beta^{\text{main}}_{\text{CL}},\ \hat\beta^{\text{alternative}}_{\text{CL}}\big),\qquad \text{Jaccard}=\frac{|E_1\cap E_2|}{|E_1\cup E_2|}\]

| Symbol | Reading / Meaning |
| --- | --- |
| \(E_1, E_2\) | Sets of nonzero edges in the two analyses |
| \(\|E_1\cap E_2\|\) | Number of edges present in both |
| \(\text{Jaccard}\) | Jaccard similarity coefficient: 0 = completely different, 1 = identical |

Reporting whether the main conclusions (strongest edges, centrality ranking, direction between constructs) hold in the alternative analysis means more than reporting an abstract correlation.

#### 4. A note on repeated CV

The cross-validation error \(\mathrm{CV}(\lambda)\) itself depends on the random fold split. Repeating the split R times and averaging, \(\overline{\mathrm{CV}}(\lambda)=\frac1R\sum_r \mathrm{CV}_r(\lambda)\), reduces the randomness in choosing λ (at the cost of R times the computation).

## ③ R Code Implement in R

Core of R/L9-2.R

```r
source("R/_setup.R")
suppressPackageStartupMessages(library(networktools))
dat <- read_course_data()
X <- dat[, vars_t(1)]; Y <- dat[, vars_t(2)]
off <- matrix(TRUE, 9, 9); diag(off) <- FALSE
# 1) sensitivity to the λ rule
rules <- c("lambda.min", "lambda.1se", "ebic")
Bs <- lapply(rules, function(r) { set.seed(2026); clpn_estimate(X, Y, rule = r) })
names(Bs) <- rules
sapply(Bs, function(B) sum(cl_only(B) != 0))            # number of CL edges per rule
sapply(Bs, function(B) names(which.max(rowSums(cl_only(B)))))   # top out-EI node
# 2) sensitivity to the random seed
arr <- sapply(1:20, function(s) { set.seed(s); clpn_estimate(X, Y)[off] })
nz  <- rowMeans(arr != 0)
table(cut(nz, c(-.01, 0, .99, 1), labels = c("Always 0", "Intermittent", "Always Nonzero")))
# 3) item redundancy
gb <- goldbricker(dat[, vars_t(1)], p = 0.05, method = "hittner2003",
                  threshold = 0.25, corMin = 0.5)
gb$suggested_reductions
```

**goldbricker parameters:** `corMin = 0.5` checks only item pairs with correlation ≥ 0.5; `threshold = 0.25` means that if fewer than 25% of the two items' correlations with the other items differ significantly, the pair is flagged as "possibly redundant" (smaller values = more similar). This is only a prompt; whether to merge depends on item content and theory.

**With few nodes, goldbricker has limited power to discriminate**

Look at the actual output for the course data (`R/output/L9-2_log.txt`): goldbricker flags 9 item pairs, 5 loneliness pairs and 4 depression pairs, all within one construct and none across constructs. This does not show that all 9 pairs "ask the same thing"; the method simply cannot tell them apart with only 9 nodes.

The reason is how it compares. For a pair of items, it compares only the two items' correlations with the remaining items. With 9 nodes there are only 7 remaining items, so the "proportion significantly different" can only take the values 0, 1/7 (≈ 0.14), 2/7 (≈ 0.29) …. A threshold of 0.25 means a pair is flagged if at most 1 of the 7 comparisons is significant. Items of the same construct already have similar patterns of correlation with the remaining items (they share the same latent trait), so almost every pair crosses the line. The fewer the nodes, the fewer "remaining items" there are to compare and the lower the power of each comparison, so the tool more easily misreports "belonging to the same construct" as "redundant content".

So in a 9-node CLPN, goldbricker's output can only be a starting point: take the flagged pairs back to the item wording, see whether they really ask the same thing (for example "I feel lonely" and "I feel lonesome"), and decide with theory whether to merge them. The same goes for reading papers: when a study with very few nodes reports "goldbricker found no redundancy" or "found a lot of redundancy", first ask whether the method can discriminate at all with that few nodes.

### Worked example: turning a problem into a review comment

Spotting a problem is only the first step; it is useful only once it is written as a comment the authors can act on. Take "over-reading centrality" from the ten common problems and write it in three parts, problem — reason — suggestion:

**Problem:** "The discussion calls 'Sleep problems', the node with the highest out-EI, the 'core symptom' and recommends targeting it first." **Reason:** "Supplementary Table S3 shows a CS-coefficient of 0.21 for out-EI, below the usual 0.25 standard, so the ranking may change after dropping only a few participants; moreover, out-EI reflects a predictive relationship, not the effect of an intervention." **Suggestion:** "I suggest removing the term 'core symptom' and instead describing the out-EI values and their uncertainty; if the authors wish to discuss implications for intervention, please present them as hypotheses to be tested in intervention studies."

Written this way, the authors know what the problem is, why it is a problem and how to fix it, so the comment is more than criticism. Keep the tone aimed at the paper, never at the authors. The numbers in the example are made up.

Complete companion script `R/L9-2.R` (34 lines, click to expand)

```r
# =====================================================================
# L9-2.R  Critical Appraisal: Are Conclusions Sensitive to Analytical Decisions?
#         (Sensitivity / robustness checks)
# Examining 3 "researcher degrees of freedom":
#   λ selection rules (lambda.min / lambda.1se / EBIC), random seeds, and item redundancy (topological overlap)
# =====================================================================
source("R/_setup.R")
suppressPackageStartupMessages(library(networktools))
log_open("L9-2_log.txt")
dat <- read_course_data()
X <- dat[, vars_t(1)]; Y <- dat[, vars_t(2)]
off <- matrix(TRUE, 9, 9); diag(off) <- FALSE
rules <- c("lambda.min", "lambda.1se", "ebic")
Bs <- lapply(rules, function(r) { set.seed(2026); clpn_estimate(X, Y, rule = r) }); names(Bs) <- rules
summ <- t(sapply(Bs, function(B) {
  CL <- cl_only(B); el <- edge_list(CL)
  c(CL_edges = sum(CL != 0), strongest_edge = paste(el$from[1], "→", el$to[1]),
    highest_outEI = names(which.max(rowSums(CL))), highest_inEI = names(which.max(colSums(CL))))
}))
print(summ)

# Random seeds: cv.glmnet splits folds randomly — do edges change across 20 random seeds?
seeds <- 1:20
arr <- sapply(seeds, function(s) { set.seed(s); clpn_estimate(X, Y)[off] })
nz <- rowMeans(arr != 0)
cat("\nAcross 20 random seeds: always non-zero CL edges =", sum(nz == 1),
    "; always 0 =", sum(nz == 0),
    "; intermittent =", sum(nz > 0 & nz < 1), "\n")
cat("→ Reports must explicitly state the random seed; repeated CV can also be used to mitigate randomness.\n")

# Item redundancy: goldbricker() identifies item pairs with highly overlapping content/correlation profiles
gb <- goldbricker(dat[, vars_t(1)], p = 0.05, method = "hittner2003", threshold = 0.25, corMin = 0.5, progressbar = FALSE)
cat("\nPotentially redundant item pairs (goldbricker):\n"); print(gb$suggested_reductions)
log_close()
```

## ④ Concept Check Instant Check

When two items have nearly the same content, what does a strong edge between them mean?

- A. The two symptoms strongly influence each other

- This is the common misreading named in this lesson: the same thing measured twice, not two symptoms acting on each other.

- B. Most likely the same construct measured twice (topological overlap), which inflates centrality (Correct)

- Correct.

- C. The network was estimated wrongly

- The estimate itself may be fine: the two items really are highly correlated in the data; the problem is how to interpret the edge.

- D. A larger λ is needed

- λ only controls the strength of the penalty; a strong edge caused by overlapping content survives at any reasonable λ.

Why is centrality "not the same" as an intervention target?

- A. The most central node is the most severe symptom and should be treated first

- Treating centrality as severity is a common misreading: centrality measures association with other nodes, not the average level of a symptom, and the two can be completely different.

- B. Centrality summarizes statistical association/prediction; it can be affected by unclear direction, overlapping content and instability, and it does not consider whether the node can be changed by intervention (Correct)

- Correct.

- C. Only betweenness centrality can represent a target

- Betweenness is even less stable in psychological networks (Lesson 6.5), and it is likewise just a summary of statistical associations.

- D. Because EI can be negative

- That EI can be negative is a computational property, not the reason centrality cannot serve as a target.

How would you check whether a CLPN conclusion is sensitive to the choice of λ?

- A. Report only lambda.min, but raise the number of bootstrap replicates to 5,000

- The bootstrap addresses sampling uncertainty, not whether the conclusion changes under another λ rule.

- B. Estimate with lambda.min, lambda.1se and EBIC separately and compare whether the main conclusions (strongest edges, centrality ranking, construct direction) hold (Correct)

- Correct.

- C. Set λ to 0 (equivalent to OLS) and compare with the LASSO result

- λ = 0 is not a reasonable alternative rule: it keeps every coefficient, so you would be comparing "regularize or not", not "another reasonable choice".

- D. Re-estimate with 20 different random seeds

- Plausible but wrong: changing the seed tests the randomness of the cross-validation folds, while the λ rule itself stays the same. It is also a useful sensitivity analysis, but it answers a different question.

With 20 different seeds on the course data, 11 CL edges are "sometimes there, sometimes not". What does this show?

- A. glmnet has a bug

- Not a bug: cv.glmnet splits the folds at random, and different splits choose slightly different λ.

- B. The randomness of the cross-validation folds affects whether weak edges are selected; you must report the seed and interpret weak edges with caution (Correct)

- Correct.

- C. You should pick the seed with the most edges for the main analysis

- This is exactly the misuse of researcher degrees of freedom: picking the seed after seeing the results.

- D. The seed only affects weak edges, so it need not be reported

- Plausible but wrong: it does mainly affect weak edges, but precisely because of that, if you do not report the seed, nobody can reproduce your edge count and weak edges.

lone4 has the highest out-EI under all three λ rules, but CS = 0.20. What is the most appropriate conclusion?

- A. lone4 is robustly the most important node

- Agreement across rules is not sampling stability: all three rules use the same sample.

- B. Agreement across rules does not mean sampling stability; with a low CS you still should not interpret the out-EI ranking (Correct)

- Correct: the different rules share the sampling error of the same sample.

- C. CS was computed wrongly; go by the sensitivity analysis

- The two checks answer different questions, so the results do not contradict each other, and there is no reason to think CS was computed wrongly.

- D. Switch to EBIC for the main analysis

- Changing the main-analysis rule after seeing the results breaks the analysis plan; and under EBIC lone4 also has the highest out-EI, so the CS problem remains.

## Summary Key Takeaways & Further Reading

- Ten problems: causal wording, between- vs within-person, over-reading centrality, topological overlap, choice of nodes, single-item reliability, sample size, missing data, interval, researcher degrees of freedom.

- goldbricker() can flag item pairs whose content/association patterns overlap heavily.

- Sensitivity analysis: λ rule, seed, covariates, redundant items; report whether the main conclusions hold.

- Course data: 11 edges come and go across 20 seeds; agreement across rules ≠ sampling stability.

- Review: strengths → major issues (problem–reason–suggestion) → minor issues; address the work, not the people.
