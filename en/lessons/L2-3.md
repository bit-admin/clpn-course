## ① Intuition Data Frames: A Register with One Row per Person

**From a case register to a data frame**

Picture a community center's case register: each row is one client, and each column is one piece of information (ID, gender, age, item scores, …). A data frame in R has exactly this structure: **rows = cases, columns = variables, a cell = one person's value on one variable**. The course data `clpn_sim_wide.csv` is an 800-row × 34-column data frame: 800 people and 34 variables (ID, 9 items × 3 waves, gender, age, and so on).

Each column of a data frame is a vector (Lesson 2.2). Within a column the type is the same; different columns can have different types (`id` is character, `dep1_t1` is numeric). All columns have the same length, and row 37 is the same person in every column.

There are two common ways to take out one column:

- `dat$dep1_t1`: `$` takes a column by name and gives a vector.

- `dat[, "dep1_t1"]`: the two-dimensional form of the brackets, `[row, column]`; leaving the part before the comma empty means "all rows." On an ordinary `data.frame` this also returns a vector, but on a tibble (see below) it returns a one-column tibble. To be sure you get a vector, use `dat[["dep1_t1"]]`.

In the same way, `dat[1:5, ]` takes all columns of the first 5 rows, and `dat[dat$gender == 1, ]` takes the rows of all women.

### tidyverse: a set of "verbs" for data wrangling

The tidyverse is a family of R packages with a shared design (dplyr, ggplot2, readr, tidyr, and others), developed by Hadley Wickham and colleagues. dplyr provides the core verbs for data wrangling. Each verb does one thing, and its name is an English verb:

| Verb | Works on | What it does | Social work analogy |
| --- | --- | --- | --- |
| `select()` | **columns** | Picks variables | Photocopying only the depression-scale columns of the register |
| `filter()` | **rows** | Picks cases by a condition | Looking only at clients with a depression total ≥ 10 |
| `mutate()` | columns | Creates or changes variables | Adding a "total score" column at the right edge of the sheet |
| `summarise()` | whole table → one row | Summarizes (mean, count, …) | Writing one line: "the average score is …" |
| `group_by()` | rows | Groups the data; later steps run within each group | Counting men and women separately |
| `arrange()` | rows | Sorts | Ordering cases from highest to lowest risk |

Data read with `read_csv()` (readr package), and the results of dplyr, are usually a tibble, a souped-up data frame. When printed, it shows only the first 10 rows and the columns that fit, and marks each column's type (`<chr>` character, `<dbl>` numeric), so it doesn't flood the screen; and it never turns strings into factors automatically. Apart from the bracket difference above, you use it like a data frame. Some older functions expect a vector; if a tibble gives you a strange error, try `dat$column` or `dat[["column"]]` instead.

### The pipe |>: read it as "then"

The pipe `|>` (built into R since 4.1) passes the result on its left as the first argument of the function on its right. `dat |> filter(gender == 1)` is the same as `filter(dat, gender == 1)`. The benefit is that you can chain several steps from top to bottom, like a set of instructions:

`dat |> filter(...) |> group_by(...) |> summarise(...)` reads: "take the data, then filter, then group, then summarize." Online you will also see `%>%`, the older pipe from the magrittr package; in ordinary use the two do the same thing. The RStudio shortcut for a pipe is Ctrl+Shift+M (Mac: Cmd+Shift+M), but by default it inserts `%>%`. To make it insert `|>`, tick "Use native pipe operator, |>" under Tools → Global Options → Code → Editing. All code in this course uses `|>`.

### Recoding and reverse scoring

Recoding means turning raw values into the form the analysis needs, for example 0/1 into "Male / Female" (`if_else()`), ages into age groups (`case_when()`), or reverse scoring.

Many scales include reverse-worded items. On a loneliness scale, for example, the more someone agrees with "I feel there is someone I can talk to," the *less* lonely they are. If you sum the items without reversing it first, this item cancels out part of the other items' scores; in a correlation or network analysis it correlates negatively with the other items, and the network shows confusing negative edges that come only from the direction of the wording and reflect no psychological mechanism.

$$\text{reversed score} = (\text{minimum} + \text{maximum}) - \text{raw score}$$

For an item scored 1–4: reversed = 5 − raw (1↔4, 2↔3); for 0–3: 3 − raw; for 1–5: 6 − raw.

**The course data have no reverse-worded items**

All 9 items in the simulated data already point the same way (higher = lonelier / more depressed). For a demonstration, the script reverses `social_support_t1` (1–5, higher = more support) into `support_rev = 6 − social_support_t1` (higher = less support), so that it points the same way as loneliness and depression. In real research, check the scale manual for which items need reversing, and after reversing, check that the items of the same scale are mostly positively correlated. Reversing only flips the sign of a correlation: if you pretend `lone2_t1` is reverse-worded (5 − raw), its correlation with `lone1_t1` goes from 0.456 to −0.456.

**Why social workers need to watch for this**

Scales common in social work (social support, self-efficacy, family functioning) often mix positively and negatively worded items. Volunteers who enter the data usually type in the boxes as ticked; reverse scoring is the analyst's job. If you skip it, the usual consequences are an unusually low reliability (α) and weakened correlations between the total score and other variables.

## ② Essential Math Total Scores and Group Means

$$\text{depression total}_i = \sum_{k=1}^{5} \text{dep}_{k,i}$$

\(i\)Person \(i\) (row \(i\) of the data frame).\(k\)Item \(k\) (a column).\(\text{dep}_{k,i}\)Person \(i\)'s score on depression item \(k\) (0–3), so the total ranges from 0 to 15.

This is a sum across a row, done by `rowSums()`. A group mean:

$$\bar y_g = \frac{1}{n_g}\sum_{i\in g} y_i$$

\(g\) is a group (for example, women), \(n_g\) the number of people in it, and \(\sum_{i\in g}\) means summing only over the people in that group. In R: `group_by() |> summarise(mean())`.

## ③ R Code Chaining Five Verbs

Script for this lesson: [R/L2-3.R](../R/L2-3.R).

R/L2-3.R (core part)

```r
library(tidyverse)
dat <- read_csv("data/clpn_sim_wide.csv", show_col_types = FALSE)  # a tibble (souped-up data frame)

phq <- dat |> select(id, gender, starts_with("dep") & ends_with("_t1"))  # pick columns: select
print(phq, n = 5)

# Reverse-scoring example: suppose social support needs reversing (1–5 → 5–1): new value = 6 - old value
dat <- dat |>
  mutate(support_rev = 6 - social_support_t1,                         # reverse-scoring example
         dep_sum_t1  = rowSums(across(c(dep1_t1:dep5_t1))))           # total score
dat |>
  mutate(gender_label = if_else(gender == 1, "Female", "Male")) |>
  group_by(gender_label) |>                                            # group
  summarise(n = n(), dep_mean = mean(dep_sum_t1), sd = sd(dep_sum_t1)) |>  # summarize
  print()
n_high <- dat |> filter(dep_sum_t1 >= 10) |> nrow()   # pick rows: filter
cat("Number of participants with depression sum score >= 10: ", n_high, "\n", sep = "")
```

**Line by line**

- `starts_with("dep") & ends_with("_t1")`: picks the columns that "start with dep and end with _t1," that is, the 5 depression items at T1. Other selection helpers include `contains()` and `matches()`.

- `dep1_t1:dep5_t1`: the colon means "every column from this one to that one" (it depends on the column order). `across()` bundles these columns and hands them to `rowSums()`.

- `if_else(condition, yes, no)`: gives "Female" when the condition is TRUE, otherwise "Male."

- `n()`: the number of people in the group. `summarise()` shrinks each group to one row. The course data have no missing values; with real data that do, `mean()` returns NA, so write `mean(x, na.rm = TRUE)` and report how many people each group actually used with `sum(!is.na(x))`.

- `dat <- dat |> mutate(...)`: the result must be assigned back to `dat`; otherwise the new variable is only printed, not saved. This is one of the most common beginner mistakes.

### Worked example: one pipe for loneliness totals by gender

Task: using the T1 data, compute each person's loneliness total, keep only people aged 60 and over, and compare the mean and the count by gender. Write out the plan first (the most important step), then turn it into code:

1. **mutate**: create a column `lone_t1` = the sum of the 4 loneliness items (added across the row).

2. **filter**: keep the rows with `age >= 60`.

3. **group_by**: group by `gender`.

4. **summarise**: for each group, compute the count, mean, and standard deviation.

```r
source("R/_setup.R")      # finds the course root folder and defines small helpers such as read_course_data() (Lesson 2.4)
library(dplyr)
dat <- read_course_data()  # same as read.csv("data/clpn_sim_wide.csv")
res <- dat |>
  mutate(lone_t1 = lone1_t1 + lone2_t1 + lone3_t1 + lone4_t1) |>   # added across the row
  filter(age >= 60) |>
  group_by(gender) |>
  summarise(n = n(), M = mean(lone_t1), SD = sd(lone_t1)) |>
  ungroup()
res
```

If you don't run `source("R/_setup.R")` first, R reports `could not find function "read_course_data"`: this function does not come with R; the course defines it in `R/_setup.R`. If you'd rather not depend on it, replace the second line with `dat <- read.csv("data/clpn_sim_wide.csv")`, as long as your working directory is the course root folder (Lesson 2.4).

When you read the result, look at `n` first: the two group counts should add up to the total number of people aged 60 and over, which you can check with `sum(dat$age >= 60)`. This "check the head count" step takes almost no time but catches many wrangling errors, such as a filter condition written the wrong way round, the wrong comparison sign (`>` vs. `>=`), or rows with missing values quietly dropped.

### A classic trap: sum() inside mutate

Many beginners write `mutate(lone_t1 = sum(lone1_t1, lone2_t1, lone3_t1, lone4_t1))`. Every person then gets the same huge "total," because `sum()` adds up all items for **everyone**. There are two correct ways to add across a row: join the columns with `+`, or use `rowSums(across(lone1_t1:lone4_t1))`. Afterwards, glance at the result with `head()`: are the totals between 4 and 16, and do they differ from person to person?

**Common mistakes**

- **A single equals sign in filter.** `filter(gender = 1)` gives an error; you must write `filter(gender == 1)`.

- **Forgetting ungroup after group_by.** The grouping "sticks" to the data, so a later mutate computes within groups (for example, group means), and the result is quietly wrong.

### Many columns at once: across() and selection helpers

The CLPN data have 27 item columns (9 items × 3 waves); typing them one by one is slow and it's easy to miss one. dplyr has helpers that pick columns by a naming pattern: `starts_with("lone")` picks all loneliness items, `ends_with("_t1")` all wave-1 columns, and `lone1_t1:lone4_t1` a block of adjacent columns. With `across()` you can apply the same operation to several columns. For example, `summarise(across(ends_with("_t1"), mean))` computes the mean of every T1 item at once, and `mutate(across(starts_with("dep"), ~ .x / 3))` divides every depression item by 3. `~ .x / 3` is a short way to write a small function, where `.x` stands for "the current column."

Watch out: `ends_with("_t1")` also picks up covariates such as social_support_t1 and sleep_hours_t1. After selecting, print the names to check, with `names(select(dat, ends_with("_t1")))`.

### How to debug a long pipe

When a pipe of five or six steps fails, don't stare at the whole block. Starting from the first line, select one more line each time and run it, and check whether each step's output is what you expect: is the number of rows right, has the new column appeared, is the range of values sensible? The step after which the result goes wrong is where the problem is.

### arrange and count as checks

`arrange(dat, desc(age))` sorts by age from oldest to youngest, which helps you check extreme values: are the ages in the first and last few rows plausible? `count(dat, gender)` is short for `group_by(gender) |> summarise(n = n())`. When you get new data, running count on every categorical variable quickly reveals coding problems, such as gender taking values other than 0 and 1.

### rename: giving a column a name you'll remember

`rename(dat, lone_total = lone_t1)` is written "new name = old name." It's easy to get this the wrong way round, so take care. Renaming doesn't change the data; it only makes later code and output easier to read.

## ⑤ Exercises Hands-On Practice

#### Exercise 2.3-A: Select, reverse, total, group

On the course's simulated questionnaire data: select the T1 depression items (PHQ-style), "pretend" one item is reverse-worded and rescore it (for example social support, or practice by treating `lone2_t1` as reverse-worded), create a total score, and compute means by gender.

Reference code and key points

```r
library(tidyverse)
dat <- read_csv("data/clpn_sim_wide.csv", show_col_types = FALSE)
res <- dat |>
  select(id, gender, starts_with("dep") & ends_with("_t1"), social_support_t1) |>
  mutate(support_rev = 6 - social_support_t1,                 # 1–5 → 5–1
         dep_sum_t1  = rowSums(across(dep1_t1:dep5_t1)),
         gender_label = factor(gender, levels = c(0, 1), labels = c("Male", "Female")))
res |>
  group_by(gender_label) |>
  summarise(n = n(), dep_mean = mean(dep_sum_t1), lack_support_mean = mean(support_rev))
cor(res$social_support_t1, res$support_rev)    # -1: reversing only flips the direction
```

Key points: (1) the reverse-scoring formula is right; (2) `cor()` confirms that the correlation between the original and reversed versions is −1; (3) the depression mean is 4.21 for women and 3.41 for men (matching the script output); (4) one sentence explaining why reverse-worded items must be dealt with before the analysis.

#### Exercise 2.3-B: Loneliness totals and a high-risk list

Create the T1 loneliness total `lone_sum_t1` (4 items, range 4–16). Keep the people with a loneliness total ≥ 13 and a depression total ≥ 10, sort them by depression total from high to low, and keep only `id` and the two totals. How many people are there?

Reference code

```r
high <- dat |>
  mutate(lone_sum_t1 = rowSums(across(lone1_t1:lone4_t1)),
         dep_sum_t1  = rowSums(across(dep1_t1:dep5_t1))) |>
  filter(lone_sum_t1 >= 13, dep_sum_t1 >= 10) |>

```

Result: 22 people. To think about: what could a "high on both" list like this be used for in services? (Prioritizing outreach, referral for assessment.) What should you be careful about when using it? (A screening cutoff is not a diagnosis; protect privacy.)

## Summary Three Takeaways

- Data frame: rows = cases, columns = variables; `$` takes a column as a vector, `[row, column]` indexes in two dimensions.

- dplyr verbs: select picks columns, filter picks rows, mutate creates variables, group_by + summarise summarize by group; chain them with `|>`, and remember to assign the result to save it.

- Reverse reverse-worded items before analysis: reversed = minimum + maximum − raw. Next lesson: [2.4 Installing Packages, Importing Data, and Project Management](L2-4.html).
