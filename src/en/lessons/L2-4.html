① IntuitionToolboxes, Bookshelves, and Files That Can Be Found

"But it runs on my computer!"

Xiao Lin sent an analysis script to a collaborator, who got an error the moment they ran it: cannot open file 'C:/Users/XiaoLin/Desktop/thesis/data_final_v2.csv': No such file or directory. Of course the collaborator's computer has no "Xiao Lin's desktop." Then came another error: there is no package called 'qgraph', because the collaborator hadn't installed that package. This lesson deals with both problems: where packages come from and how to load them, and where to keep files so that other people's computers can find them too.

Packages: adding new tools to R

The functions that come with R (such as mean() and lm()) are only the basic tools. Extra tools written by others are bundled as {{T:packages|}} and offered for free download on {{T:CRAN|Comprehensive R Archive Network}} (R's official package repository). The tools CLPN needs, glmnet (LASSO), qgraph (drawing networks), and bootnet (stability analysis), are all packages.

Analogy: buying a book vs. taking it off the shelf

install.packages("qgraph") is buying the book: it downloads the package from CRAN and installs it on your computer, once per computer. The exception is upgrading R: packages are stored separately for each "major.minor" version of R, so you must reinstall them not only after a major upgrade (4.x → 5.0) but also after a minor one (such as 4.4 → 4.5); only after a patch upgrade (such as 4.5.0 → 4.5.1) can you keep using the packages you have. library(qgraph) is taking the book off the shelf and putting it on your desk: every time you open R (each new session), you have to take it down once before you can use its functions. So even after a package is installed, you still need library() the next time you open R. This also tells two errors apart: there is no package called 'bootnet' means you haven't bought it yet (not installed), so run install.packages("bootnet"); could not find function "cv.glmnet" often means the book is on the shelf but you didn't take it down (installed, but no library(glmnet)).

  • In install.packages() the package name needs quotes; in library() it usually doesn't.
  • Don't put install.packages() in an analysis script that you run every time (it would download the package again each time). The course scripts use an "install only what is missing" pattern (see R code).
  • To use one function without loading the whole package, write package::function, for example psych::describe(dat). This also avoids confusion when two packages have a function with the same name (such as dplyr::filter() and stats::filter()).
  • Red text when a package loads is not necessarily an error: many packages print startup messages or notes that some function has been "masked." Real errors start with Error.

Working directory and paths: where does R look for files?

When R reads or writes a file, it starts from a "current folder" called the {{T:working directory|}}, which you can see with getwd().

  • Absolute path: written from the root of the disk, for example C:/Users/XiaoLin/Desktop/thesis/data.csv. It works only on your own computer.
  • {{T:Relative path|}}: written from the working directory, for example data/clpn_sim_wide.csv ("this file in the data folder inside the working directory"). As long as the other person's working directory is also the project folder, R finds it.

Windows paths use a backslash \, but inside an R string \ is the escape character, so write a forward slash / or a double backslash \\ instead.

Why not write setwd("C:/Users/...")?

setwd() changes the working directory with an absolute path. On another computer, under another user name, or after you move the folder, the script stops working; it depends on the folder layout of your own computer, so others cannot reproduce it. A better way is an RStudio project.

RStudio projects: one folder = one analysis

An {{T:RStudio project|}} is simply a folder with a .Rproj file in it. When you open RStudio by double-clicking the .Rproj, the working directory is set to that folder automatically, so every relative path works straight away. The course folder already contains clpn-course.Rproj. To create a new project: File → New Project → New Directory (or Existing Directory).

The recommended folder structure (which is the structure of this course folder clpn-course/, showing only the parts that matter for R; this is what you get after unzipping clpn-course.zip):

clpn-course/
├── clpn-course.Rproj     ← double-click to open the project
├── data/                 ← raw data (read-only; never edit by hand)
└── R/                    ← analysis scripts (in this course: R/L2-4.R and others)
    ├── solutions/        ← exercise solutions
    └── output/           ← results, figures, and logs written by the scripts

The principle: raw data are read-only. All cleaning and computing happen in scripts, and results are written to output/. Then anyone who gets the whole folder can open the .Rproj, run the scripts in order, and reproduce every result from the raw data (the "checkable report" in Lesson 9.3 builds on this). For your own projects, create an RStudio project with the same structure.

The first line of every course script is source("R/_setup.R"). That is a relative path, so it already requires the working directory to be the clpn-course folder; opening RStudio through clpn-course.Rproj guarantees this. Once loaded, _setup.R checks again: it looks at the current working directory and then up through its parent folders (at most 3 levels up, so 4 folders in all) for a folder that contains data/clpn_sim_wide.csv. If it finds one, it sets that folder as the working directory (and stores results in R/output/); if not, it stops with an error.

If you see cannot open file 'R/_setup.R' or "Cannot find course root": first run getwd() in the Console to see where you are; then close RStudio and reopen it by double-clicking clpn-course.Rproj (or use the menu Session → Set Working Directory → Choose Directory… and select the clpn-course folder). Also check that you opened the unzipped clpn-course folder and that data/clpn_sim_wide.csv exists.

Garbled Chinese text: an encoding problem

Computers store text as numbers according to an {{T:encoding|}}. The international standard is UTF-8, but Excel on Chinese-language Windows often saves CSV files in GBK (also called GB2312 / CP936). If you read a GBK file as UTF-8, the Chinese characters turn into gibberish (such as "鐢锋€�"), and sometimes you get the error invalid multibyte string. Fixes:

  • State the encoding when reading: read_csv("file.csv", locale = locale(encoding = "GBK")), or read.csv("file.csv", fileEncoding = "GBK").
  • In Excel, save as "CSV UTF-8 (Comma delimited)."
  • Save the script itself as UTF-8 in RStudio too (File → Save with Encoding → UTF-8); otherwise Chinese comments and labels in the script become garbled. In the long run, keep all data and scripts in UTF-8.
Social work context: from an online survey platform to R

Many social work studies collect data on online survey platforms (in China, Wenjuanxing or Tencent Surveys; elsewhere, for example, Qualtrics). The exported Excel / CSV files often have long column names in Chinese, text answers ("strongly agree" instead of 4), and total rows. Good habits: (1) put the original export into data/ unchanged; (2) in the script, rename the columns (such as lone1_t1) and recode text answers into numbers; (3) write a data dictionary (the course's data/data_dictionary.csv is an example) that records what each variable means and what values it takes.

② Essential MathNo New Formulas This Lesson

This is an "engineering" lesson with no new statistical formulas. You only need to remember one "equation":

$$\text{reproducible result} = \text{raw data} + \text{script} + \text{software versions}$$

When all three are fixed, anyone can get the same result. Record software versions with sessionInfo() or packageVersion("glmnet"); when the result involves a random process (cross-validation, bootstrap), also fix the random seed with set.seed() (Lesson 3.5).

na = c("", "NA", "999") tells R to treat empty cells, "NA", and 999 as missing. Many survey platforms and SPSS files use 999, 99, or −9 for "not answered." Left as they are, these are treated as real scores, which pushes means up and distorts correlations and network edges.

Worked example: a five-step checkup after importing new data

Suppose a partner agency sends you survey.csv. Don't rush into a model; do these five steps first. Each one catches a common kind of problem:

```r d <- read.csv("data/survey.csv") # 1. Import (path relative to the project root) dim(d) # 2. Rows = number of people? Columns = items + demographics? str(d) # 3. Are the column types right? Item scores should be int/num, not chr summary(d) # 4. Are the ranges right? Do 9, 99, -9 appear on a 1–4 item? colSums(is.na(d)) # 5. How much is missing in each column? # If 99 / -9 mean missing, change them to NA in the item columns only (not across the whole table: on a 0–100 variable, 99 may be a real score) item_cols <- grep("^(lone|dep)", names(d), value = TRUE) for (v in item_cols) d[[v]][d[[v]] %in% c(99, -9)] <- NA ```

Replace values only in the item columns: on a 0–100 variable such as life satisfaction, 99 may be a real answer. Go column by column, following the questionnaire's codebook.

More on SPSS value labels

When you read a .sav file with value labels using read_sav(), those columns have the type haven_labelled and print labels such as "1 [never]". Before computing statistics, you usually strip the labels with haven::zap_labels() to keep only the numbers, and turn categorical variables into factors with haven::as_factor(). Also check whether "user-missing values" defined in SPSS (such as 99) have been converted to NA.

A fixed opening for every script

Every script in this course starts the same way: a comment saying what the script does and which lesson it belongs to; then source("R/_setup.R") for the shared preparation (finding the course root folder, creating the R/output folder, setting the plot font, and defining shared functions such as read_course_data()); then library() for the packages this script needs; then reading the data. Use the same order in your own scripts: purpose comment → load packages → read data → analyze → save output. Then anyone who opens the script can see within the first 10 lines what it depends on and which data it reads.

SummaryThree Takeaways

  • install.packages("pkg") once per computer, library(pkg) once per session.
  • Use an RStudio project + relative paths, not setwd("C:/..."); raw data are read-only, and results are produced by scripts.
  • After importing, check types, ranges, and missing-value codes first; gibberish text is usually an encoding problem (GBK vs. UTF-8). Next lesson: {{L:2.5}}.
