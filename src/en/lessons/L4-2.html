① IntuitionOne dataset, two layouts

Two kinds of register

A community center records attendance and mood ratings for the members of a group over three sessions. Chen, one of the social workers, keeps a "one row per person" register: each member has one row, and the ratings for sessions 1, 2 and 3 sit side by side in different columns of that row. Wu, another social worker, keeps a "one row per visit" log: each time a member attends, he adds a row with three columns, "member ID," "session number," and "rating." The two records contain exactly the same information; only the layout differs.

Chen's register is in {{T:wide format|}}: one row per person, with the same variable at different waves in different columns (lone1_t1, lone1_t2, lone1_t3). The course data file clpn_sim_wide.csv is in wide format: 800 rows.

Wu's log is in {{T:long format|}}: one row per person per wave, a wave column that says which wave it is, and one column per variable (lone1). In long format the course data have 800 × 3 = 2400 rows.

Converting between the two is called {{T:reshaping|}}. Different analyses need different formats:

AnalysisFormat neededWhy
Fitting a CLPM / RI-CLPM in lavaan (Module 5)WideSEM treats each "variable × wave" as a separate variable (lone2 ~ lone1 + dep1)
CLPN (Module 7)Wide, then split into two matrices, d1 (T1 items) and d2 (T2 items)Each T2 item is regressed on all T1 items
Multilevel models (lme4), trajectory plots in ggplotLong"Wave" is a variable; each observation is a row
Summaries by wave (mean per wave)Long is easiergroup_by(wave) |> summarise()

Neither format is better; it depends on the tool you use next. A practical workflow: keep the raw data in wide format (the way the survey system exports it); convert to long format on the fly when you need a plot or a multilevel model, and don't bother saving the long version.

Naming conventions: names a computer can read

Wide data can be reshaped automatically because they follow one {{T:naming convention, e.g. sleep_t1|}}: item_t<wave>. The benefits:

  • Clear at a glance: dep3_t2 is depression item 3 at wave 2.
  • Can be split by code: pivot_longer(names_sep = "_t") cuts each column name at _t into "item name" and "wave."
  • Can be selected by code: paste0(items, "_t", 1) builds all T1 column names; ends_with("_t2") picks every T2 variable.
  • Hard to misalign: every T1 variable has a T2 counterpart with a predictable name.

Survey platforms often export column names such as "Q1, Q2 … Q27" or the full text of each question. The first thing to do with new data is to rename the columns according to the data dictionary.

{{T:participant ID|}}: the lifeline for alignment

Why must T1 and T2 be aligned by ID when you split them?

CLPN uses "the T1 items in row 37" to predict "the T2 items in row 37," which only makes sense if both rows are the same person. If T1 and T2 come from two files sorted differently (say, the T2 file is sorted by submission time) and you simply paste the two tables side by side, row 37 might be Xiao Wang at T1 but Xiao Li at T2. The result: every relationship across time is scrambled into random noise. In this lesson's R code, after deliberately shuffling the order of T2, the T1–T2 correlation of depressed mood drops from 0.432 to 0.008, all autoregressive and cross-lagged effects "disappear," and R gives no error at all.

The fix: always merge with a function that matches on ID, such as left_join(t1, t2, by = "id"), never by pasting rows side by side; after splitting, check with identical(d1$id, d2$id).

Analogy: pairing socks

If you pair the socks from the washing machine in the order they come out, most pairs will be wrong. You pair them by pattern (ID). Reshaping and merging data work the same way.

The "recipe" for wide ↔ long

Wide → long: pivot_longer() (tidyr package). You tell it which columns to "lengthen" (all columns except id: -id), how to split the column names (names_sep = "_t"), and what the two parts are (names_to = c(".value", "wave")). ".value" is special: it means "the first part (e.g., lone1) becomes a new column name, and the values go into that column." The second part (1, 2, 3) goes into a new column called wave.

Long → wide: pivot_wider(). You tell it which column supplies the new column names (names_from = wave), which columns supply the values (values_from = item columns), and what separator to use when gluing the names together (names_sep = "_t").

Always check after reshaping: does the number of rows equal "people × waves"? Does converting back give exactly the original data (all.equal(), as this lesson's script does)? Are the IDs aligned? And spot-check one person (e.g., filter(long, id == first(id))) against the wide data.

② Essential MathTwo matrices that match row for row

CLPN needs two matrices:

$$\mathbf{D}_1 = \begin{pmatrix} x_{1,1}^{(1)} & \cdots & x_{1,p}^{(1)}\\ \vdots & & \vdots\\ x_{n,1}^{(1)} & \cdots & x_{n,p}^{(1)}\end{pmatrix},\qquad \mathbf{D}_2 = \begin{pmatrix} x_{1,1}^{(2)} & \cdots & x_{1,p}^{(2)}\\ \vdots & & \vdots\\ x_{n,1}^{(2)} & \cdots & x_{n,p}^{(2)}\end{pmatrix}$$
\(x_{i,j}^{(t)}\)
Score of person \(i\) on item \(j\) at wave \(t\).
\(n\)
Number of people (rows); must be the same in both matrices.
\(p\)
Number of items (columns); column \(j\) must be the same item in both matrices.

Two alignment conditions: rows aligned (row \(i\) of \(\mathbf{D}_1\) and row \(i\) of \(\mathbf{D}_2\) are the same person) and columns aligned (column \(j\) is the same item). Equation \(j\) of a CLPN predicts column \(j\) of \(\mathbf{D}_2\) from all columns of \(\mathbf{D}_1\). If the rows are misaligned, the equation is meaningless; if the columns are misaligned, you will misread "T1 depressed mood → T2 sleep problems" as an autoregressive effect.

Rows in long format = \(n\times T\) = 800 × 3 = 2400; columns in long format = id + wave + number of items = 2 + 9 = 11.

③ R Codepivot_longer, pivot_wider, and d1/d2

Script: R/L4-2.R.

```r R/L4-2.R (core part) source("R/_setup.R") library(tidyverse) wide <- read_csv("data/clpn_sim_wide.csv", show_col_types = FALSE) |> select(id, all_of(c(vars_t(1), vars_t(2), vars_t(3)))) # Keep only id + the 27 item columns # Wide -> long: column name "lone1_t2" is split at "_t" into item name (.value) and wave long <- wide |> pivot_longer(-id, names_to = c(".value", "wave"), names_sep = "_t") print(head(long)); cat("Long format rows =", nrow(long), "(= 800 participants * 3 waves)\n") # Long -> wide: convert back and check that it matches the original wide2 <- long |> pivot_wider(names_from = wave, values_from = all_of(items), names_sep = "_t") wide2 <- wide2[, names(wide)] # Put the columns back in the original order cat("Identical to original data after pivoting back to wide?", isTRUE(all.equal(as.data.frame(wide), as.data.frame(wide2))), "\n") # Split off d1 and d2 -- vars_t() keeps the item order the same d1 <- wide |> select(all_of(vars_t(1))) d2 <- wide |> select(all_of(vars_t(2))) stopifnot(nrow(d1) == nrow(d2), identical(sub("_t1", "", names(d1)), sub("_t2", "", names(d2)))) # Check the order cat("d1 and d2 row counts and item ordering check passed ✔\n") ``` ```out Output (R/output/L4-2_log.txt) # A tibble: 6 × 11 id wave lone1 lone2 lone3 lone4 dep1 dep2 dep3 dep4 dep5 1 P001 1 3 2 2 2 0 0 1 0 0 2 P001 2 3 4 3 2 1 1 1 0 1 3 P001 3 4 2 3 1 0 0 0 0 0 4 P002 1 1 2 1 2 0 0 1 0 1 5 P002 2 2 1 2 2 0 1 1 2 1 6 P002 3 2 1 2 1 0 1 3 3 0 Long format rows = 2400 (= 800 participants * 3 waves) Identical to original data after pivoting back to wide? TRUE d1 and d2 row counts and item ordering check passed ✔ ```
Code notes
  • vars_t(1) (defined in _setup.R) returns the 9 T1 item column names in a fixed order: lone1–lone4, dep1–dep5. all_of() tells select(): "select the columns named in this character vector, every one of them" (a missing name is an error, so you cannot drop a column without noticing).
  • The wave column is character <chr> ("1", "2", "3"). When you need it as a number (e.g., time as a predictor), use mutate(wave = as.integer(wave)), or add names_transform = list(wave = as.integer) to pivot_longer().
  • stopifnot(): stops with an error as soon as a condition is false. A check written into the script is far more reliable than "having a look."
  • sub("_t1", "", names(d1)): deletes "_t1" from the column names, giving lone1 … dep5, which are then compared one by one with the d2 names after "_t2" is removed.

Two pitfalls, demonstrated

```r Pitfall 1: ends_with("_t1") picks up columns you don't want read_csv("data/clpn_sim_wide.csv", show_col_types = FALSE) |> select(ends_with("_t1")) |> names() ``` ```out Output (R/output/L4-2_log.txt, continued) [1] "lone1_t1" "lone2_t1" "lone3_t1" [4] "lone4_t1" "dep1_t1" "dep2_t1" [7] "dep3_t1" "dep4_t1" "dep5_t1" [10] "social_support_t1" "sleep_hours_t1" "life_sat_t1" ```

In the raw data, social support, sleep hours and life satisfaction also end in _t1, so they would end up in d1 too, with no matching T2 columns: d1 would have 12 columns and d2 only 9 (and T2 has an extra help_seek_t2). That is why the course scripts use an explicit list of column names, vars_t(). A shortcut such as select(ends_with("_t1")) is safe only when the data frame contains nothing but item columns (L4-2.R first drops the other columns with select(id, all_of(...))).

```r Pitfall 2: pasting two differently sorted files together by row number t1 <- wide |> select(id, ends_with("_t1")) set.seed(42) t2 <- wide |> select(id, ends_with("_t2")) |> slice_sample(prop = 1) # Simulate "the T2 file is in a different order" bad <- bind_cols(t1, select(t2, -id)) # Side by side by row number good <- left_join(t1, t2, by = "id") # Matched by ID cor(bad$dep1_t1, bad$dep1_t2) cor(good$dep1_t1, good$dep1_t2) ``` ```out Output (R/output/L4-2_log.txt, end) [1] 0.008359975 [1] 0.4322975 ```

Pasted together by row number, the T1–T2 correlation of depressed mood falls from 0.432 to 0.008, and R gives no warning at all. left_join(x, y, by = "id") keeps every row of x and attaches the columns of y by id; if someone missed T2, their T2 columns are NA (Lesson 4.3).

What about variables that don't change over time?

Gender and age are measured once, so their column names have no "_t1". If you run pivot_longer(-id, ...) directly, names_sep cannot split "gender," and you get an error or wrong columns. Two ways out: ① first select() only id and the wave-specific items, reshape, and then attach the demographic variables again with left_join(by = "id"); ② write -c(id, gender, age) in pivot_longer, and these columns are repeated on every row automatically.

A typical use of long format: person-mean centering

Lesson 4.1 split each score into "the person's average level (between-person) + this wave's deviation from that average (within-person)." In long format this takes two steps: long |> group_by(id) |> mutate(dep_pm = mean(dep1), dep_dev = dep1 - dep_pm) |> ungroup(). dep_pm is each person's mean over the three waves, the same value on all three of that person's rows; dep_dev is how far above or below their own mean they are at each wave, and each person's three values add up to 0. Doing the same in wide format means writing a formula for every item and every wave, which is tedious and error-prone. You will use this split again and again when within-person questions come up (Lessons 5.3 and 7.5).

Common mistakes
  • pivot_wider produces list columns and the warning "Values are not uniquely identified". The same id × wave appears in more than one row, usually because an id was entered twice or a distinguishing variable is missing. Find the duplicates first with count(long, id, wave) |> filter(n > 1).
  • Column names that can't be split. When lone1_T1, lone1.t1 and t1_lone1 are mixed together, names_sep can't help. Make the names follow one rule with rename() or names(d) <- ... first, then reshape.

Mini exercise: which format?

Which format does each task need? ① Fitting a two-wave CLPM in lavaan; ② plotting the three-wave loneliness trajectories of 800 people; ③ computing each person's mean depression over the three waves. Answers: ① wide; ② long (one row per person per wave, group = id); ③ either. In wide format, average the three columns with rowMeans(); in long format, use group_by(id) |> summarise(m = mean(dep)). When a problem has two solutions, pick the one you are least likely to get wrong.

Exercise 4.2-A: Reshaping and aligning 3 waves × 6 items

Convert a wide dataset with 3 waves × 6 items to long format and back; then split off d1 (the 6 items at T1) and d2 (the 6 items at T2) and check that the row counts and IDs match exactly. (Use lone1–lone3 and dep1–dep3 from the course data as the 6 items.)

Reference code ```r library(tidyverse) wide <- read_csv("data/clpn_sim_wide.csv", show_col_types = FALSE) six <- c("lone1", "lone2", "lone3", "dep1", "dep2", "dep3") w6 <- wide |> select(id, all_of(paste0(rep(six, 3), "_t", rep(1:3, each = 6)))) # 1 + 18 columns l6 <- w6 |> pivot_longer(-id, names_to = c(".value", "wave"), names_sep = "_t") dim(l6) # 2400 rows × 8 columns w6b <- l6 |> pivot_wider(names_from = wave, values_from = all_of(six), names_sep = "_t") isTRUE(all.equal(as.data.frame(w6), as.data.frame(w6b[, names(w6)]))) # TRUE d1 <- w6 |> select(id, all_of(paste0(six, "_t1"))) d2 <- w6 |> select(id, all_of(paste0(six, "_t2"))) stopifnot(nrow(d1) == nrow(d2), identical(d1$id, d2$id)) X <- as.matrix(d1[, -1]); Y <- as.matrix(d2[, -1]) # Drop id: the two matrices CLPN uses ```

Notes: rep(six, 3) repeats the 6 item names 3 times, and rep(1:3, each = 6) gives 1,1,1,1,1,1,2,…; paste0() glues them into 18 column names. Check three things: rows in long format = 800 × 3; converting back reproduces the original; d1 and d2 have the same number of rows and identical IDs.

Exercise 4.2-B: Plotting means from long format

Using the long data long, compute the mean of each of the 9 items at each wave, and draw 9 lines in ggplot showing how each mean changes across waves (x axis: wave; y axis: mean; color: item). Hint: first run pivot_longer() once more to lengthen the items as well.

Reference code ```r long |> pivot_longer(lone1:dep5, names_to = "item", values_to = "score") |> group_by(wave, item) |> summarise(m = mean(score), .groups = "drop") |> ggplot(aes(x = wave, y = m, colour = item, group = item)) + geom_line() + geom_point() + labs(x = "Wave", y = "Item mean") ```

You will see 9 almost flat lines: the loneliness items average about 2.2 (scored 1–4), the depression items about 0.75 (scored 0–3). The average level is stable, but that does not mean individuals don't change (the spaghetti plot in Lesson 4.1). group = item tells ggplot to connect the points item by item.

SummaryThree things to take away

  • Wide format has one row per person (for lavaan and CLPN); long format has one row per person per wave (for multilevel models and trajectory plots). pivot_longer() / pivot_wider() convert between them.
  • Consistent item_t<wave> names let you reshape and select columns automatically; an explicit list of column names is safer than pattern matching.
  • Merge by ID (left_join); after splitting, check row counts, IDs and item order. Misalignment gives no error, but it ruins the results. Next lesson: {{L:4.3}}.
